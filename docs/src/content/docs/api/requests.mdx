---
title: Requests
description: Everything a program can ask of nerdr's API — the state, an agent's screen, scrolling it and the size it is shown at, messages, keys, answers, new tabs, terminals and agents, reviews, closing tabs and quitting.
---

A request is one line of JSON with an `op`, what to do, and the
parameters it takes. `id` is optional and can be any JSON value: the
answer carries it back, so a program can match answers to requests.

```json
{"id": 7, "op": "read", "target": "9f3c01aa", "lines": 20}
```

The answer is `{"id": …, "result": …}`, or `{"id": …, "error": "…"}`
when the request could not be done. The error is a sentence meant for
people. Requests are answered one at a time, in the order they were
sent, and an answer can be interleaved with [events](../events/).

Tabs, agents and terminals are identified by the IDs in
[`state`](#state). A tab's and an agent's ID stay the same for as long
as it is there, across restarts of nerdr too; a terminal's for as long
as nerdr runs. A tab's ID is also the ID of its first agent.

| `op` | Parameters | Does |
|---|---|---|
| [`state`](#state) | | Everything at once |
| [`subscribe`](#subscribe) | | Events from now on |
| [`read`](#read) | `target`, `lines` | What an agent or terminal shows |
| [`send`](#send) | `agent`, `text` | Queue a message for an agent |
| [`type`](#type) | `target`, `text`, `keys` | Type into an agent or terminal now |
| [`scroll`](#scroll) | `target`, `lines` | Scroll a full-screen agent's history |
| [`view`](#view) | `target`, `cols`, `rows` | Show an agent or terminal at your screen's size |
| [`unview`](#unview) | `target` | Stop showing it |
| [`answer`](#answer) | `question`, `yes` | Answer one of nerdr's questions |
| [`seen`](#seen) | `agent` | Look at an agent, as visiting it does |
| [`wake`](#wake) | `tab` | Wake a sleeping tab |
| [`repos`](#repos) | | The repositories a tab can be made in |
| [`new_tab`](#new_tab) | `repos`, `branch`, `agent`, `model`, `task` | Make a tab |
| [`new_terminal`](#new_terminal) | `tab` | Open a terminal in a tab |
| [`new_agent`](#new_agent) | `tab`, `agent`, `model`, `task` | Start another agent in a tab |
| [`review`](#review) | `agent`, `by`, `model` | Have an agent's work reviewed |
| [`close_tab`](#close_tab) | `tab`, `remove` | Close a tab |
| [`quit`](#quit) | | Stop nerdr and its agents |

## state

Every tab with its agents, terminals and branches; the agents that need
you; nerdr's open questions; and the agents that can be started.

```json
{"id":1,"op":"state"}
```

```json
{"id":1,"result":{
  "root": "/home/you/develop",
  "tabs": [{
    "id": "9f3c01aa",
    "name": "fix-login",
    "dir": "/home/you/.nerdr/worktrees/fix-login",
    "task": "Fix the login redirect",
    "status": "tests pass, writing the PR",
    "agents": [
      {"id": "9f3c01aa", "num": 1, "kind": "claude", "model": "opus", "state": "blocked", "context_percent": 41},
      {"id": "1b2e77d0", "num": 2, "kind": "codex", "state": "working", "reviewer": true, "messages_waiting": 1}
    ],
    "terminals": [{"id": "c4d5e6f7", "name": "terminal", "command": "make test", "running": true}],
    "branches": [{"repo": "web", "branch": "fix-login", "ahead": 3, "behind": 0,
                  "lines_added": 40, "lines_deleted": 12, "files_changed": 3,
                  "pushed": true, "pr": 412, "pr_state": "OPEN", "ci": "pass",
                  "pr_url": "https://github.com/you/web/pull/412"}]
  }],
  "waiting": ["9f3c01aa"],
  "questions": [],
  "agents": ["claude", "codex"]
}}
```

**A tab** has its `name` and the folder it works in (`dir`). It may also
have a `group`, the `task` it was given, and a `status`: what its agent
last said of where the work stands (`nerdr status`).

**An agent** has its `num`, the number the tab shows it by ("2:codex"),
and its `kind` and `model`. `reviewer` is set for an agent that reviews
another's work, and `messages_waiting` counts the messages waiting to
be typed in to it. Its `state` is one of:

| `state` | The agent |
|---|---|
| `starting` | is starting |
| `working` | is at work |
| `background` | has finished its turn, with commands it started still running |
| `blocked` | asks you something, on its screen |
| `done` | has finished, and you have not looked at it yet |
| `idle` | waits at its prompt |
| `asleep` | was put to sleep while its tab was not looked at (`sleep_after`) |
| `exited` | has stopped |

**`waiting`** lists the agents that need you, in the same order as
nerdr's waiting list: the ones asking first, then the ones that are done,
oldest first.

**A terminal** has its `name`, as `nerdr read` calls it ("terminal",
"terminal 2"), and `command`, the last command an agent ran in it.

**A branch** shows each repository's branch: how far it is ahead of or
behind its base, its changes, and its pull request and CI once nerdr has
looked them up. `pr_state` is GitHub's (`OPEN`, `CLOSED`, `MERGED`), and
`ci` is `fail`, `pending` or `pass`.

### Questions

`questions` are what nerdr asks you, waiting for a yes or no. They are
not what an agent asks on its screen; that is an agent in the `blocked`
state, which you answer with [`type`](#type).

```json
{"id": 4, "kind": "plugin_run", "text": "fix-login would run the plugin deploy",
 "agent": "9f3c01aa", "plugin": "deploy", "values": {"env": "staging"},
 "dir": "/home/you/.nerdr/worktrees/fix-login", "until": "2026-11-14T21:03:00+01:00"}
```

| `kind` | Asks |
|---|---|
| `repo_setup` | May the setup in `.nerdr.toml` of `repos` run in new worktrees? A tab being made waits for the answer; with no, it is made without the setup |
| `plugin_run` | May `agent` run `plugin` with `values` in `dir`? If not answered by `until`, the answer is no |

`text` asks the question in one sentence, ready to show.

## subscribe

From now on, the program is also sent [events](../events/). The answer
is `{"id":…,"result":{}}`. Ask for `state` after subscribing, and follow
the events from there.

## read

The last `lines` lines (80 if not given) of what an agent or a terminal
shows, as plain text:

```json
{"id":2,"op":"read","target":"9f3c01aa","lines":15}
```

```json
{"id":2,"result":{"text":"Do you want to proceed?\n❯ 1. Yes\n  2. No, and tell Claude what to do differently\n","cols":120,"rows":40,"alt":true,"wheel":true}}
```

`target` is an agent's or a terminal's ID (`agent` works too, for an
agent). An agent that is not running is an error. `cols` and `rows` are
the size of its screen, the one the lines are laid out for: see
[`view`](#view).

`alt` is true when the program is full-screen, on the terminal's
alternate screen. That screen keeps no scrollback: the text is only what
fits on it, and the rest of the program's history only the program has.
`wheel` is true when, on top of that, the program takes the mouse wheel,
so [`scroll`](#scroll) works on it now. Both are read in the same look
as the text. A nerdr older than `scroll` leaves them out.

## send

Queues `text` as a message for `agent`. nerdr types it in, and presses
enter, once the agent is at its prompt, never while it is asking
something, the same way messages between agents work. Use this for
anything you would tell the agent in words.

```json
{"id":3,"op":"send","agent":"9f3c01aa","text":"Also cover the logout redirect"}
```

The answer comes as soon as the message is queued. The agent's
`messages_waiting` counts it until it is typed in.

## type

Types into an agent or a terminal right away: first `text`, as a paste,
then `keys`. Use it to answer what an agent asks on its screen, to
interrupt it, or to run a command in a terminal.

```json
{"id":4,"op":"type","target":"9f3c01aa","keys":["1","enter"]}
{"id":5,"op":"type","target":"c4d5e6f7","text":"make test","keys":["enter"]}
{"id":6,"op":"type","target":"9f3c01aa","keys":["esc"]}
```

A key is a single character, typed as it is, or one of: `enter`, `esc`,
`tab`, `shift-tab`, `backspace`, `space`, `up`, `down`, `left`, `right`,
`home`, `end`, `pageup`, `pagedown`, `ctrl-a`, `ctrl-c`, `ctrl-d`,
`ctrl-e`, `ctrl-l`, `ctrl-o`, `ctrl-r`, `ctrl-t`, `ctrl-u`, `ctrl-z`.

If this connection [views](#view) the agent or terminal, it gets this
connection's size first, as when you type in nerdr's window. The same
goes for [`send`](#send).

## scroll

Turns the mouse wheel over a full-screen agent or terminal, so it
scrolls its own history, as the wheel does in nerdr's window:

```json
{"id":9,"op":"scroll","target":"9f3c01aa","lines":3}
```

`lines` is how many steps of the wheel: up, to older text, when
positive, down when negative. A program scrolls as far for each as it
does for a step of a real wheel, often three lines. At most 50 steps go
either way, more being taken as 50; `0` does nothing. The answer is
`{"id":…,"result":{}}`; [`read`](#read) again to see where it got to.

It works only while `read` says `wheel`: the program is on the
alternate screen and takes the mouse. Otherwise the answer is an error
saying the program `does not scroll`, and nothing is sent. Keys are not
sent in place of the wheel, as `up` makes many agents bring back an
earlier prompt. A program on the main screen has its history in the
text `read` gives.

If this connection [views](#view) the program, scrolling counts as
being active in it, as typing does: it gets this connection's size
first. `target` is an agent's or a terminal's ID (`agent` works too,
for an agent). A nerdr older than `scroll` answers `no op "scroll"`.

## view

Shows an agent or a terminal at the size of your screen, `cols` columns
by `rows` rows, so the program lays itself out for it:

```json
{"id":7,"op":"view","target":"9f3c01aa","cols":48,"rows":30}
```

```json
{"id":7,"result":{"cols":48,"rows":30}}
```

A program has one size, while nerdr's window, a phone and a tablet may
all show it. The one that was active in it last sets it: that viewed it
first, typed to it (`type`, `send`), scrolled it (`scroll`), or
changed the size it shows it at; in nerdr's window, typing, clicking or
moving to it, or resizing the window. The others show the same screen at a size not their own,
wrapped or cut. The result is the size the program has now: yours, or
that of one active in it since.

Say `view` again every 20 seconds or so while you show the program. A
view not said again within 60 seconds runs out, and so does every view
of a connection that closes: a phone locked or a machine asleep is not
left setting the size. Saying it again at the same size keeps the view,
but does not take the size back from one active since; at another
size, it does. When the view that sets the size goes, the one active
before it takes over; with none left, the program keeps the size it
has. A program no one has shown starts at 120 × 40 (see
`headless_cols` in the [configuration](../../configure/configuration/)).

`cols` is brought within 20 to 500, and `rows` within 5 to 300.
`target` is an agent's or a terminal's ID (`agent` works too, for an
agent).

## unview

Stops showing an agent or a terminal, when you leave its screen or the
app goes to the background:

```json
{"id":8,"op":"unview","target":"9f3c01aa"}
```

The size of the one active in it before you holds, or, with no one
left, the size it has.

## answer

Answers one of nerdr's [questions](#questions): `yes` true or false.
nerdr goes on as if you had answered in its window, and the question
goes from every client.

```json
{"id":9,"op":"answer","question":4,"yes":true}
```

A question already answered, or timed out, is an error.

## seen

Counts as you looking at the agent, as visiting its tab does: a `done`
agent turns `idle`, and messages that were held back because you typed
to it go on. A phone app sends this when you open an agent.

```json
{"id":10,"op":"seen","agent":"9f3c01aa"}
```

## wake

Wakes the agents of a tab that were put to sleep while it was not
looked at (`sleep_after`).

```json
{"id":11,"op":"wake","tab":"9f3c01aa"}
```

## repos

The repositories nerdr finds, to make a tab in:

```json
{"id":12,"op":"repos"}
```

```json
{"id":12,"result":[{"name":"api","path":"/home/you/develop/api"},{"name":"web","path":"/home/you/develop/web"}]}
```

## new_tab

Makes a tab on a new branch `branch` in the repositories named in
`repos`, the same way `nerdr tab new` does for an agent. Its agent is
started with `task`.

```json
{"id":13,"op":"new_tab","repos":["api"],"branch":"fix-timeout",
 "agent":"claude","task":"The /orders call times out on large carts; find out why and fix it"}
```

- `agent` is one of `state`'s `agents`, the first of them if not given;
  `model` is optional.
- The answer, `{"branch":"fix-timeout"}`, says the tab is being made.
  Making its worktrees takes a moment. The tab then arrives with a
  `tab_opened` [event](../events/), or a `notice` says why it was not
  made, for example a branch of that name already being there.
- If a repository has a setup in `.nerdr.toml` that you have not
  allowed, a `repo_setup` question comes first, and the tab is made
  once it is answered.

The request is refused at once if the branch name is not valid, a
repository or agent is not there, or the tab limit (`max_tabs`) is
reached.

## new_terminal

Opens a terminal in the tab's worktree, in a new pane after the others,
as the TUI's new-terminal key does. nerdr's window keeps the keyboard
where it is.

```json
{"id":14,"op":"new_terminal","tab":"9f3c01aa"}
```

```json
{"id":14,"result":{"id":"c4d5e6f7"}}
```

The result is the terminal's ID, to [`type`](#type) a command into and
[`read`](#read). The tab's `terminals` have it, and a `tab`
[event](../events/) says so.

## new_agent

Starts another agent beside the tab's own, in a new pane after the
others, working in the same worktree. nerdr's window keeps the keyboard
where it is.

```json
{"id":15,"op":"new_agent","tab":"9f3c01aa","agent":"codex","task":"Write the tests for the redirect"}
```

```json
{"id":15,"result":{"id":"1b2e77d0"}}
```

- `agent` is one of `state`'s `agents`, and must be given. `model` is
  optional.
- `task`, if given, is the agent's first message, typed in once it is
  at its prompt, as with [`send`](#send).
- The result is the new agent's ID. It comes with an `agent`
  [event](../events/), and has the next `num` in the tab.

## review

Starts a code review of an agent's work, the same way the TUI's review
pane does, or adds a reviewer to the review going on.

```json
{"id":16,"op":"review","agent":"9f3c01aa","by":"codex"}
```

- `by` is the kind of agent to review with, one of `state`'s `agents`.
  If not given, it is the one the config gives (`[review] agent`).
- `model` is optional; without it the reviewer runs the model the
  config gives it (`[review.models]`), if any.
- The answer comes at once. nerdr then looks at the worktree, and the
  reviewer arrives as an agent with `reviewer` set, or a `notice` says
  why not, for example that nothing has changed to review.

The request is refused if the agent is itself a reviewer, if a reviewer
of the same kind is reviewing already, if the agent is busy with the
findings of a review, or if the agent runs in a sandbox and the reviewer
would not.

## close_tab

Closes a tab, stopping every agent, terminal and reviewer in it, as the
TUI's close dialog does.

```json
{"id":17,"op":"close_tab","tab":"9f3c01aa","remove":true}
```

```json
{"id":17,"result":{"text":"closed fix-login and deleted its worktree"}}
```

- Without `remove`, the worktrees and branches are kept, and the tab
  can be opened again from them.
- With `remove`, the worktrees are deleted too, but never by force. The
  request is refused, and the tab stays open, if a worktree has changes
  that are not committed, or commits that are on no remote and not in a
  merged pull request. The error says where. Commit or push them, or
  close without `remove`.
- The branches are kept, unless the pull request of every one is merged
  on GitHub with the head the branch has: then they are deleted as well,
  as pressing enter in the close dialog does.
- `tab` must be the tab's own ID, not the ID of another agent in it.

The answer comes once the tab's programs have stopped and its worktrees
are gone; `text` says what was done. A `tab_closed` [event](../events/)
follows. If an agent committed after the worktrees were looked at, and
before it was stopped, the tab is closed but the worktrees are kept, and
the answer is an error saying so.

## quit

Stops nerdr for its folder, as quitting in its window does: every agent,
terminal and plugin stops, and the tabs are kept for the next time nerdr
starts there. A window open on it closes. `nerdr stop` sends this.

```json
{"id":18,"op":"quit"}
```

The answer, `{"id":18,"result":{}}`, says nerdr is quitting, and the
connection then closes. While the agents stop it can close before the
answer comes: a program that sent `quit` can take the connection closing
as the same answer. A `quit` to a nerdr already quitting is answered
with an error, `nerdr is quitting`.
