All settings live in `~/.config/nerdr/config.toml`, and all are optional.
Change them in nerdr with `ctrl+q s`, or edit the file: nerdr reloads it
within a few seconds and tells you which changes need a restart.
[Saved prompts](../../panel/tasks/#saved-prompts) are kept beside it, in
`prompts.toml`.

## The settings dialog

`ctrl+q s` lists every setting, the review settings and each agent's
command, arguments and environment, in five tabs: General (keys, folders,
programs, keep awake and plugins), Screen, Tabs, Notifications, and Agents
(code review and each agent). Bold values are set by you; dimmed ones are
defaults.

| Key | Action |
|---|---|
| `↑` / `↓` | Select a setting |
| `tab` / `shift+tab` | Next or previous tab; or click one |
| `?` | Help for it |
| `enter` | Toggle, cycle or edit it |
| `←` / `→` | Change a number or a choice |
| `d` | Restore the default |

Type a list as words separated by spaces, with quotes around a value
that has spaces, and a variable as `NAME=value`. Changes are saved at once without rewriting the
rest of the file. Settings read only at start, such as `prefix`, `mouse`,
`fps`, `worktrees_dir`, `install` and `data_dir`, say "from
nerdr's next start". New agent arguments apply to the next agent started;
`ctrl+q a r` restarts the current one.

Below the settings, the dialog shows the version of nerdr that runs on
its machine (`ctrl+o` moves the dialog to the next machine), and this
nerdr's version when the two differ. Machines may run different versions
as long as they speak the same protocol, so this is no warning. A machine
that is not connected says so, with the version it had when it was last
connected.

## Keys and mouse

| Setting | Default | |
|---|---|---|
| `prefix` | `"ctrl+q"` | The key before every nerdr command: any `ctrl+<letter>`. Avoid keys your agents use. |
| `mouse` | `true` | Clicks, menus, the wheel and selecting text. Off, the terminal keeps its own selection. |
| `function_keys` | `true` | Label the panel's screens F1–F5. Off, label them with their `ctrl+q` keys (`g c`, `g g`, `e`, `k`, `h`), for keyboards where the F-keys are hard to reach. |

If the prefix letter is also a command key, that command moves to `q`,
and quit moves to the prefix letter. Menus and hints follow.

## Screen

| Setting | Default | |
|---|---|---|
| `tab_bar` | `"left"` | Where the tabs go: `top`, `left`, or `left-small` (status lights only). |
| `tab_details` | `true` | Changes, pull request and CI in the tab list. |
| `bottom_bar` | `true` | A row along the bottom: on the left, failing CI, pull request and issue news, tabs waiting and tabs merged across all tabs; in the middle, the active tab's branch, ahead and behind, files not committed, commits not pushed, lines changed and pull request; on the right, its tasks and the saved prompts. Each is a button for its screen. Off, the news and the active tab's details are in the bar at the top. |
| `key_panel` | `false` | nerdr's keys and what each does, all the time, in a narrow column on the right; a group's keys open below it when its key is pressed. Off, they show in a box in the middle after the prefix. |
| `prefix_hint` | `true` | A box in the middle of the screen with every key after the prefix, the most used first, when you wait a moment after it. |
| `pane_min_width` | `60` | The narrowest a pane is shown side by side, in columns; past it, the panes used longest ago fold away. |
| `diff_colors` | `"github"` | How F1 draws the changes: `github`, like GitHub's diffs, or `nerdr`. |
| `status_lights` | `"dots"` | `dots`, or `symbols`: ◐ working, ◎ background process, × needs input, ✓ done. |
| `fps` | `60` | The most screen redraws per second, 1–120. Read at start. |

### Screen redraws

`fps` caps how often nerdr redraws the screen. A lower value uses less
CPU: at 30, an idle nerdr uses about a third less, and typed text and
agent output can appear up to one frame later, about 33 ms. Above 60
makes little difference, since nerdr redraws an agent's output at most
about 60 times a second.

## Folders

| Setting | Default | |
|---|---|---|
| `repo_dirs` | `[]` | More folders with repositories, such as `["~/code", "~/work"]`, besides the one nerdr starts in. |
| `worktrees_dir` | `"~/worktrees-nerdr"` | Where new worktrees go; created as needed. A relative path is taken from the folder nerdr starts in, or beside it when that is a repository. |
| `data_dir` | `""` | Where nerdr keeps what agents record about a change. See [below](#where-nerdr-keeps-its-data). |
| `install` | asked at first start | Where nerdr may install skills, plugins and hooks for the agents: `home`, `worktree` or `off`. See [Skills](../../panel/skills/#where-skills-are-installed). |
| `enabled_skills` | all | The skills that are on. See [Skills](../../panel/skills/#turning-skills-off). |

### Where nerdr keeps its data

`data_dir` holds what the agents record about a change: their
explanations (`why.jsonl`, `order.jsonl`), code reviews (`reviews.jsonl`,
`review-sessions.jsonl`), walkthroughs and handoffs (`handoff/`).

| `data_dir` | Where, and for how long |
|---|---|
| Empty (default) | `.git/nerdr/` in the repository's Git folder: shared across worktrees, outside version control, kept when a worktree is deleted. |
| A relative path, such as `.nerdr` | Inside each worktree, kept out of git through `.git/info/exclude`. For sandboxes that only reach the worktree. Deleted with the worktree. |
| An absolute path, such as `~/nerdr-data` | One folder, with a subfolder per repository named after its main checkout. |

The `.jsonl` files hold one JSON object per line, appended under a lock.
At start, nerdr removes reading orders for deleted branches and reused
branch names, except with an absolute `data_dir`. Why notes are kept.

## Tabs

| Setting | Default | |
|---|---|---|
| `max_tabs` | `20` | The most tabs open at once; `0` for no limit. |
| `cold_days` | `5` | Mark tabs cold after this many idle days; `0` never. |
| `sleep_after` | `0` | Minutes before agents that are done, seen and out of sight are stopped; they continue when you visit the tab. `0` never. See [Agents asleep](../../use/progress/#agents-asleep). |
| `close_merged` | `true` | Say in a tab's status panel when its pull requests are merged. |
| `headless_cols` | `120` | Columns an agent or terminal starts at when no window or app shows it yet, such as one started from the [API](../../api/requests/#view) with nerdr's window closed. `0` for the default. |
| `headless_rows` | `40` | Rows, the same way. |
| `port_base` | `20000` | The first port of the ranges given to tabs. See [Ports of the tab's own](../../use/tabs/#ports-of-the-tabs-own). |
| `ports_per_tab` | `10` | Ports in each tab's range, which an agent gets from `nerdr ports` and the tab's terminals, plugins and setup from `NERDR_PORT` and `NERDR_PORT_END`. `0` gives tabs none. Open tabs keep the range they have. |

## Notifications and GitHub

| Setting | Default | |
|---|---|---|
| `notify` | `"all"` | When to notify: `all`, `blocked` (needs input), `done` or `off`. Done is told once the tab's work is over, not when an agent hands it on to a reviewer or another agent in the tab. |
| `pr_notify` | `true` | Tell you about failed checks and new reviews on your pull requests. Off, GitHub is not asked, unless [`[auto]`](#automatic-asks) turns something on. |
| `issue_notify` | `true` | Tell you about issues newly assigned to you. Off, GitHub is not asked. |
| `github_refresh` | `90` | Seconds between GitHub checks of the tab on screen, 15–3600; other checks scale with it. |
| `claude_status_line` | `true` | Start claude with nerdr's status line, which reports the rate limits and then shows yours. See [Usage](../../use/progress/#usage-and-rate-limits). |

## Programs

| Setting | Default | |
|---|---|---|
| `shell` | `""` | The shell for terminal panes; empty uses `$SHELL`. |
| `editor` | `""` | What `o` in F1 opens a file in, such as `"code"` or `"nvim"`; empty uses `$VISUAL`, then `$EDITOR`, then `vim`. |
| `worktree_editor` | `""` | What `ctrl+q o` opens the worktree in; empty uses `code`. |
| `browser` | `""` | The command a URL is opened with, such as `"firefox"` or `"open -a Safari"`; empty uses `$BROWSER`, then `xdg-open` or `open`. |

## Plugins

| Setting | Default | |
|---|---|---|
| `confirm_plugin_runs` | `false` | Ask before an agent runs any plugin. See [Writing plugins](../plugins/#saying-yes-to-each-run). |
| `open_global_plugins` | `true` | Open the global plugins' dialog by itself when an agent runs a global plugin. See [Private and global plugins](../plugins/#private-and-global-plugins). |

## Keeping the machine awake

| Setting | Default | |
|---|---|---|
| `keep_awake` | `"busy"` | `busy`: no sleep while an agent or reviewer works, and for a minute after. `always`: while nerdr runs. `off`. |
| `keep_screen_on` | `false` | Also keep the screen from blanking and locking. |
| `keep_screen_max` | `60` | Minutes after your last key or click in nerdr that the screen is kept on. |

On Linux, nerdr holds a logind inhibitor against idle and requested
suspend (`systemd-inhibit --list` shows it), and with `keep_screen_on`
asks the desktop through `org.freedesktop.ScreenSaver`, which GNOME,
Cinnamon, KDE and others follow. On macOS, nerdr uses `caffeinate -i`,
adding `-d` for the screen. Closing a laptop lid still follows the
system's lid setting.

With agents on a server, `keep_awake` is that machine's setting and
keeps it awake; `keep_screen_on` keeps the screen on where you run
nerdr.

logind lets only a login session block sleep. nerdr on a server, started
over ssh by the nerdr in front of you, is in none, so it blocks idle
alone, and notes so in the [history (F5)](../../panel/history/), not in
the bar. That holds off logind's own suspend when idle (`IdleAction`),
which is all a server without a desktop has, but not a suspend asked
for, such as a desktop's after it has been idle a while. For a server
with a desktop that suspends, add a polkit rule on it, with your user
name for `you`, in `/etc/polkit-1/rules.d/50-nerdr-keep-awake.rules`:

```js
polkit.addRule(function (action, subject) {
  if (action.id == "org.freedesktop.login1.inhibit-block-sleep" &&
      subject.user == "you") {
    return polkit.Result.YES;
  }
});
```

Or turn the server's suspend when idle off in its power settings.

## Review

The `[review]` table sets up [code review](../../use/code-review/).

```toml
[review]
auto = false              # review without asking
when = "ready"            # with auto: "ready" when the agent says so, "turn" after every turn that changes the worktree
agent = "other"           # a different kind of agent, or a name such as "codex"
rounds = 2                # review rounds before leaving findings to you
send_findings = "ask"     # ask: keep in F3 and ask; auto: send to the agent directly
model_names = "nerdr"     # nerdr: nerdr finds the agent's own name for a model you named; agent: the agent does

[review.args]             # arguments for reviewers, after the agent's own
codex = ["--sandbox", "read-only"]

[review.models]           # the model each agent reviews with, in its own names; set by picking one in the review pane
codex = "gpt-6-astra"
claude = "opus"
```

`agent = "other"` picks Codex to review Claude, and Claude to review the
others. If that agent is not installed, nerdr picks another that is.

With `auto` and `when = "ready"`, the review starts when the agent says
its work is ready with `nerdr request-review`. The
`nerdr-request-review` skill tells it to do so when review is on. This
way, work that is only half done is not reviewed. Agents without that skill are
reviewed after every turn.

When you ask the agent for a review with a model, in your own words
("review it with codex on astra 6.2"), the agent passes the model on as
you said it, and `model_names = "nerdr"` has nerdr find the reviewer's own
name for it among the models that agent lists: `gpt-6.2-astra`. A name
that could be several models goes back to the agent, which asks you
which. With `model_names = "agent"`, nerdr takes only the reviewer's own
names, and the agent looks the name up itself, which takes it a few
steps longer.

## Automatic asks

The `[auto]` table has nerdr ask a tab's agent by itself when something
happens to the pull request of the tab's branch. It is off by default.

```toml
[auto]
ci_failed = "off"         # a check failed: ask the agent to fix it, with the job's log
review_comments = "off"   # a review that is not an approval: ask for draft replies
conflicts = "off"         # the PR conflicts with its base: ask the agent to rebase
max_tries = 3             # sent by itself at most this many times in a row per PR
wake = false              # may wake a tab that is asleep or cold
```

Each event is one of these:

- `off`: nothing is done. nerdr still tells you of failed checks and new
  reviews, as `pr_notify` says.
- `ask`: nerdr writes the message that `f` or `a` in
  [F2](../../panel/github/) would write, and keeps it in the tab's F3.
  You are told in the bar, in the history (F5) and on the desktop. Read
  it, then send it.
- `auto`: the message is sent to the tab's agent when the agent is idle,
  without you reading it first.

nerdr acts only on your own open pull requests, the ones it watches for
`pr_notify`, and only on a branch that a tab works on. It acts only on
what changes while it watches, not on a check that was already failing.

- `ci_failed` waits until no check of the run is still going, so the
  agent gets every failing job in one message. It acts once for each
  head commit: running the same job again does not send it again, but a
  push that fails again does.
- `review_comments` acts on a review by someone else that is not an
  approval. The message asks for draft replies to every review and
  comment, as `A` does, and says that nothing is to be posted.
- `conflicts` acts when GitHub says the pull request conflicts with its
  base. The message asks the agent to rebase onto the base, resolve the
  conflicts and run the tests. It quotes nobody.

None of the messages ask the agent to commit or push. You do that once
you have looked at the work.

With `auto`, the message waits in F3, ticked to be sent by itself, until
the agent is idle. The tab's panel shows an `auto:` row while it waits,
and after it is sent, until you send the agent something else. When it
is sent, you are told as with `ask`. If an unsent one of the same kind
is still waiting, the new one takes its place.

Some things make `auto` act as `ask` for that one message. nerdr tells
you which one:

- The message would quote someone who is not you or an owner, member or
  collaborator of the repository (`review_comments`).
- The branch is in a fork (`ci_failed`).
- nerdr has sent one by itself `max_tries` times in a row for the same
  pull request. The count starts again when the checks pass, the pull
  request is approved, or the conflict goes away.
- The tab is asleep or cold (`❄`, no activity for `cold_days` days) and `wake` is off.
- A repository's `.nerdr.toml` set it to `auto`, and you have not
  allowed that file (see below).

nerdr checks the last two, and your settings, again just before it sends
a waiting message. If `auto` was turned off, or the `.nerdr.toml` changed,
the message stays in F3 for you. A message you tick or edit in F3 is
yours, and goes as you set it. If GitHub does not answer when nerdr reads
the pull request for a message, it tries again at the next few looks.

A message nerdr wrote that has not been sent yet is taken back when a
later look finds the trouble gone: the checks pass on that commit, the
conflict is resolved, or the pull request is closed. The history (F5)
records it. In a tab with several repositories, the message names the
worktree and branch it is about.

nerdr watches your pull requests while `pr_notify` is on, or while
`[auto]`, in your config or in the `.nerdr.toml` of a repository a tab
works in, turns anything on. It asks GitHub as often as
[`github_refresh`](#notifications-and-github) says: every two minutes at the default.

<Aside type="caution" title="auto sends what others wrote, unread">
Review comments and CI logs contain text written by others. A CI log
holds what your tests, your dependencies and the code under test print.
Any of it can hold instructions meant for the agent, and the agent acts
on them within its permissions. With `ask`, you read the message first.
With `auto`, nobody does. Turn `auto` on only for repositories whose
reviewers and builds you trust, and preferably for agents in a sandbox.
See [Security](../../reference/security/#automatic-asks).
</Aside>

## Agents

`[agents.<name>]` tables set how each agent is started: its command,
arguments, environment, a wrapper or sandbox. See
[Agents and sandboxes](../agents/).

```toml
[agents.claude]
args = ["--model", "opus", "--permission-mode", "acceptEdits"]
env = { MAX_THINKING_TOKENS = "16000" }

[agents.copilot]
command = ["my-sandbox", "--", "copilot"]
args = ["--allow-all"]
sandboxed = true

[agents.opencode]
command = ["my-sandbox", "--agent", "opencode", "--"]
check_command = ["my-sandbox", "exec", "--"]  # what the sandbox check runs through
sandboxed = true
sandbox_check = "once"  # check until one passes, not at every start
```

`check_command` is only for a sandbox wrapper that picks the agent with
an option or by default, so that nerdr cannot put its sandbox check in
the agent's place in `command`. See
[Checking a wrapper that picks the agent itself](../agents/#checking-a-wrapper-that-picks-the-agent-itself).
`sandbox_check = "once"` trades some of the check's safety for a quicker
start; see [Checking once](../agents/#checking-once).

A wrapper that is a short script can be kept in the config as
`[wrappers.<name>]`, and a `command` or `check_command` that starts with
the name runs it. See
[A wrapper script in the config](../agents/#a-wrapper-script-in-the-config-wrappers).

```toml
[wrappers.my-wrapper]
script = '''
exec my-sandbox --allow-write="$HOME/.cache/tool" "$@"
'''
```

## Servers

`[[servers]]` lists other machines whose agents nerdr shows beside this
machine's, each reached over SSH. See
[Several machines in one nerdr](../../use/remote/#several-machines-in-one-nerdr).

```toml
[[servers]]
name = "box"          # how the tab bar names it: no spaces, colons or quotes
ssh = "box"           # the host as ssh knows it; the name when left out
folder = "~/src"      # the folder there whose tabs nerdr shows; ~ when left out
```

The Machines dialog (`ctrl+q d`) adds and removes servers here too.

## Which machine a setting is for

With agents on other machines, each machine's config applies there. The
keys about what you see and how nerdr reaches you are read where you run
nerdr:

`prefix`, `mouse`, `function_keys`, `tab_bar`, `tab_details`,
`bottom_bar`, `key_panel`, `prefix_hint`, `pane_min_width`, `diff_colors`,
`status_lights`, `fps`, `notify`, `pr_notify`, `issue_notify`,
`editor`, `worktree_editor`, `browser`,
`keep_screen_on`, `keep_screen_max` and `[[servers]]`.

The rest are read by the machine the agents run on, from
`~/.config/nerdr/config.toml` there: `[agents]`, `[wrappers]`, `[review]`, `[auto]`, `shell`,
`repo_dirs`, `worktrees_dir`, `data_dir`, `install`, `enabled_skills`,
`max_tabs`, `cold_days`, `sleep_after`, `close_merged`, `headless_cols`,
`headless_rows`, `port_base`, `ports_per_tab`, `github_refresh`,
`claude_status_line`, `confirm_plugin_runs` and `keep_awake`, and the
plugins beside that file. An agent's command and sandbox on your laptop
never apply on a server. With nerdr on one machine, it is all one file.

In `ctrl+q s`, a machine's value is marked with its name when there are
several, and `ctrl+o` shows the next machine's. A change is written to
that machine's file.

## Per repository: `.nerdr.toml`

A `.nerdr.toml` at a repository's root copies local files into new
worktrees and runs a setup command there:

```toml
copy  = [".env", ".env.*", "certs"]
setup = "npm ci"
```

See [Getting a new worktree ready](../../use/tabs/#getting-a-new-worktree-ready-nerdrtoml).

It can also set the [automatic asks](#automatic-asks) for the
repository's pull requests, in place of your config's:

```toml
[auto]
ci_failed = "auto"
review_comments = "off"
```

An event the file leaves out follows your config. Setting one to `off`
or `ask` takes effect right away. Setting one to `auto` takes effect only
after you have allowed the file, because an agent can write it. nerdr
asks you to allow it when the next worktree is made in the repository,
and again after every change, as it does for `setup`. Until then, that
event acts as `ask`.

<Aside title="Files nerdr keeps">
Besides the config, nerdr keeps its state in `~/.local/state/nerdr/`:
saved tabs (`sessions/`), skill counts, approvals for `.nerdr.toml` and
plugins, its socket, and the temporary Git folders it makes while it
works (`tmp/`). See [How it works](../../reference/how-it-works/).
</Aside>
