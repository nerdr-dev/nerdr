## F1–F6 do nothing on my Mac

Mac laptops send brightness and volume for the F-keys unless `fn` is
held. Use `ctrl+q e 1`…`e 6`, or `m` in the panel to cycle the screens,
and set `function_keys = false` so menus show those shortcuts.

## F-keys go to the program in my terminal pane

A full-screen program in a terminal pane, such as htop, mc or vim, gets
the function keys for itself. Use `ctrl+q e 1`…`e 6` then.

## macOS will not open the binary

Gatekeeper blocks unsigned binaries received through a browser or
AirDrop. Run `xattr -d com.apple.quarantine nerdr`.

## Copying text does not reach my clipboard

nerdr copies through the terminal's OSC 52 support. GNOME Terminal and
Terminal.app lack it: install `xclip`, `xsel` or `wl-clipboard` on
Linux; macOS has `pbcopy`. If the agent uses the mouse itself, hold
`shift` while selecting.

Copy commands inside an agent or editor that use OSC 52 are not forwarded.
Select the displayed text through nerdr instead; hold `shift` if the
program captures the mouse.

## My agent's key combination does nothing

nerdr takes its prefix, `ctrl+q`, before the agent sees it. Press
`ctrl+q p` to send a `ctrl+q` to the agent, or choose another `prefix`.

## The status light is wrong

nerdr knows an agent's state best from its hooks. With `install = "off"`,
or an agent started through a wrapper that hides them, it reads the
agent's screen instead, which can mistake a long pause for done.

- **Codex** runs hooks only once it trusts them. With `install = "home"`
  nerdr sets that up; otherwise trust them yourself.
- **A sandbox** must let the agent run `$NERDR_BIN` and reach nerdr's
  socket. nerdr says so once, with the program and socket to allow, when
  an agent ends a turn without reaching it.

See [Knowing when an agent is done](../how-it-works/#knowing-when-an-agent-is-done).

## An agent in a sandbox cannot use nerdr's commands

The sandbox must pass the `NERDR_*` variables through, allow running
`$NERDR_BIN`, and allow connecting to `~/.local/state/nerdr/nerdr.sock`.
The command's error says which is missing. See
[What a sandbox must allow](../../configure/agents/#what-a-sandbox-must-allow).

## Git says a transport is not allowed

After a sandboxed agent has worked in a repository, nerdr refuses host
Git push, and fetch other than of a new tab's base from `origin` over SSH
or HTTPS. Transport and authentication helpers can run scripts from the
agent's worktree.
The message names the repository and the tab or folder its sandbox
history is from. Run the operation inside the sandbox, or inspect the
work and use your own terminal. Local status and diffs remain available
unless another unsafe Git setting blocks them.

A new tab is still made in such a repository. When `origin` is reached
over SSH or HTTPS, nerdr fetches the base as usual. Otherwise the branch
starts from the base as it was last fetched, and nerdr says why; fetch in
your own terminal first to start from the newest.

If you never run agents in a sandbox, or trust what is in the repository
now, have nerdr forget its sandbox history: **Forget sandbox history…**
in the tab's menu, or `nerdr sandbox clear REPO` in the folder you start
nerdr in, with nerdr not running. See [Security](../security/).

If a notice names an executable Git setting, nerdr may refuse all Git in
that repository, including status. This applies to custom proxy, remote
transport, alternate-reference and object hooks; the full list is on the
security page. Remove the named setting only if it is no longer needed,
or use Git inside the sandbox or your own terminal after inspecting the
work. Global GPG/1Password signing programs and credential helpers are
suppressed instead, so they do not cause this whole-repository refusal.

## The agent does not resume its conversation

nerdr resumes the conversation it knows the agent had. For codex and agy,
it learns which one after the agent's first turn. If resuming fails at
once, nerdr starts a new conversation.

## A task was not sent

nerdr never types a task while the agent asks a question or a review is
going on. If the agent did not take it up, nerdr says so and pauses the
queue (`✉n⏸`) until you visit the tab. When it says the task was typed in
but not sent, the text is still in the agent's input box, although
Enter was pressed again: press Enter in its pane. See
[Automatic messages](../how-it-works/#automatic-messages).

## I closed a tab by mistake

Quit nerdr (Quit, not Close: a core left running would write over it)
and copy a snapshot from
`~/.local/state/nerdr/sessions/snapshots/` over the session file. nerdr
keeps the newest 20, at most one every 15 minutes. See
[Saved sessions](../how-it-works/#saved-sessions).

## Agents stop when I disconnect

Closing nerdr, or losing the SSH connection, leaves its agents running:
start nerdr in the same folder again to connect to them. Quitting stops
them. With `NERDR_HOLDER=0`, nerdr runs the agents itself and they stop
with it.

On a server, agents that stop when you log out of it are ended by
systemd-logind. See
[Agents that stop when you log out](../../use/remote/#agents-that-stop-when-you-log-out).

## A server is grey

nerdr could not reach that server's core, and a tab there says why. It
keeps trying on its own; `r` on one of its tabs tries now, and logs in if
SSH asks for a password. "no nerdr on box" means `nerdr` is not on the
PATH of a login shell there: set it up in `~/.profile` or `~/.zprofile`.
A message about versions says which machine to update. See
[Other machines](../../use/remote/#a-grey-machine).

## Too many calls to GitHub

`ctrl+q g` counts git and `gh` calls per tab and by command. Raise
`github_refresh` to check less often, or turn off `pr_notify` and
`issue_notify`.
