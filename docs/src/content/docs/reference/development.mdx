nerdr is written in Go, a single static binary with no runtime
dependencies.

## Build

```sh
git clone https://github.com/nerdr-dev/nerdr && cd nerdr
make build      # ./nerdr
make install    # into $(go env GOPATH)/bin
make all        # binaries for Linux and macOS, amd64 and arm64, in dist/
```

## Tests

```sh
make test   # unit tests, with the race detector
make e2e    # the real binary in a pseudo-terminal with a fake agent:
            # setup, worktrees, status lights, review panel,
            # quit, resume and close
make vet
make fmt
```

To start the real Claude in a test tab and print its screen without
sending it a task:

```sh
NERDR_E2E_CLAUDE=1 go test -tags e2e ./internal/e2e -run TestRealClaude -v
```

## Profiling

With `NERDR_PROFILE` naming a folder, the client, the core and the
holder each take a CPU profile from their start, into
`<role>-<pid>.cpu` there. `SIGUSR2` ends it, and the process then writes
a heap (`.heap`) and an allocation profile (`.allocs`) beside it and runs
on. The core and the holder take the variable only when they start, so
quit nerdr first (Quit, not Close). Send the signal only to the
processes named in the folder: a nerdr that is not profiling ends on it.

The folder must exist, or nothing is written; use a new one each time,
so the signals go only to this run's processes:

```sh
PROF=$(mktemp -d); echo "$PROF"
NERDR_PROFILE=$PROF nerdr
# later, in another terminal, with PROF set to the folder printed above:
for f in "$PROF"/*.cpu; do p=${f##*-}; kill -USR2 "${p%.cpu}"; done
go tool pprof -top "$PROF"/client-*.cpu
```

## The docs

This site lives in `docs/` and is built with
[Starlight](https://starlight.astro.build). Each page is a file in
`docs/src/content/docs/`, and the sidebar is set in
`docs/astro.config.mjs`.

```sh
cd docs
npm ci
npm run dev       # http://localhost:4321/nerdr/, reloads as you edit
npm run build     # checks every link, writes dist/
```

A push to `main` that changes `docs/` publishes the site to GitHub Pages.

## Releases

Push a tag to release:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The Release workflow runs the tests, then
[GoReleaser](https://goreleaser.com) (`.goreleaser.yaml`) builds the four
binaries with the tag as `nerdr version`, puts them on a GitHub release
as `nerdr-<os>-<arch>.tar.gz` with `checksums.txt`, and updates the cask
in [nerdr-dev/homebrew-tap](https://github.com/nerdr-dev/homebrew-tap).
The archive names carry no version, so `releases/latest/download/` always
finds the newest; the install script, `docs/public/install.sh`, depends
on that.

The tap needs a repository secret, `HOMEBREW_TAP_TOKEN`: a fine-grained
token with write access to the contents of `nerdr-dev/homebrew-tap`.
Without it the release is made and the tap is left alone.

To try a release build without publishing anything:

```sh
goreleaser release --snapshot --clean   # writes dist/
```
